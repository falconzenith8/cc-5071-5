# 姿态交接演练视窗 · Pose Handoff Lab

游戏角色在**指定事件发生时**从动画控制交给受力姿态（ragdoll）：交接直接用当前骨骼的世界姿态与可估计速度初始化刚体链，不瞬移回默认站姿；交接后角色在场景接触中继续运动，可随时恢复动画。

## 启动界面

```bash
npm install
npm run dev          # 打开 http://localhost:5173
```

生产预览：

```bash
npm run build
npm run preview      # 打开 http://localhost:4173
```

界面是唯一入口，不是脚本演示。左半屏为角色与接触点，右侧面板为场景、受击范围、控制与结果区。

## 界面怎么用

1. 选场景：**行走中 / 转身中 / 斜面上**。三者共用同一套交接内核，区别只在动画剪辑与地面。
2. 选受力范围：**全身 17 根** 或 **上半身 9 根**。选上半身时，胸骨与脊柱之间的关节标为「边界」，下肢继续由动画驱动。
3. 点 **受击并接手** 触发交接。勾选「到点自动触发受击」则在该场景的剪辑时间点自动交接。
4. 结果区显示交接是否通过，并给出**逐骨骼**诊断表：归属、关节锚点误差、单步位移、去掉预期位移后的残差、动画速度 / 写入速度 / 物理速度、铰链角度、是否接地。
5. **恢复动画** 把控制权交回剪辑；**暂停** 冻结步进；**重置** 回到 t=0。
6. 可重放输入：**开始录制** → **受击并接手** → **导出回放** 得到 JSON；**载入** 后点 **回放**，从 t=0 用同一串输入重演。
7. 若交接未通过，画面顶部出现失败提示，**用同一录制输入重演** 会从 t=0 重放同一帧，用于定位失败骨骼。

## 交接判据（结果区与测试共用）

- 关节锚点误差 < 10 mm：刚体链没有在交接时裂开。
- 姿态残差 < 30 mm：单步位移减去「动画本应走出的一步」后的真实误差，用来排除正常的动画位移。
- 速度写入误差 < 1e-6 m/s：写进刚体的速度与动画估计速度一致，证明速度是继承来的而不是归零。
- 所有权审计：动画持有的骨骼必须是运动学刚体，受力骨骼必须是动力学刚体，同一关节不会被两套系统同时写。

受击冲量在**审计的那一步之后**才施加，因此它不会污染连续性与速度继承的测量。

## 测试

```bash
npm run verify       # 交接连续性与 2s 稳定性单元测试
npm run e2e          # Playwright 端到端（需本机 Chromium 依赖）
```

单元测试覆盖三个场景的交接连续性、交接后 2 秒的有限性与关节拉伸上限，以及上半身受力的边界关节。端到端测试覆盖从界面触发、恢复、上半身边界标记、三个场景与回放导出/导入。

## 结构

- `src/core/rig.ts`：骨骼定义唯一来源（坐标、碰撞形状、关节锚点、限位）。
- `src/core/animator.ts`：确定性程序化动画，逐骨骼中心差分速度，脚部支撑保持接地。
- `src/core/physics.ts`：交接内核（刚体链构建、速度继承、审计、稳姿辅助、接触查询）。
- `src/core/simulator.ts`：模式机、输入日志、录制与重演。
- `src/view/`：Three.js 渲染；`src/main.ts` 只做界面绑定。
